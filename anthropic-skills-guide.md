# Руководство Anthropic по скиллам — в одном файле

Это официальное руководство Anthropic [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) и [страница скиллов Claude Code](https://code.claude.com/docs/en/skills), сжатые до семи правил, плюс порядок, как применить их к уже готовым скиллам и ничего не сломать. Сверено с оригиналом 02.10.2026.

**Как пользоваться.** Положи файл в любую папку и напиши агенту:

> Прочитай anthropic-skills-guide.md и примени к моим скиллам.

Или к одному: «…примени к скиллу notion». Агент сделает копию, замерит, покажет, что поменяет, и после твоего «да» поправит.

---

## Для агента: порядок работы

Скопируй чек-лист в ответ и отмечай шаги. Шаги не пропускать и не переставлять.

```
- [ ] 1. Нашёл скиллы, назвал список
- [ ] 2. Сделал копию ВНЕ папки скиллов
- [ ] 3. Замер «до» (скрипт ниже)
- [ ] 4. Показал план: что меняю сам, что только предлагаю
- [ ] 5. Получил «да», внёс правки
- [ ] 6. Замер «после» + проверка, что ни одна строка не потерялась
- [ ] 6б. Прогон задачи: старая копия против новой версии
- [ ] 7. Отчёт: таблица до/после и список «предлагаю, не применял»
```

**1. Найти.** Claude Code: личные — `~/.claude/skills/<имя>/SKILL.md`, проектные — `.claude/skills/<имя>/SKILL.md`. Другой агент — спроси у человека, где лежат скиллы.

**2. Копия.** `cp -R <папка-скилла> ~/skills-backup-<ГГГГ-ММ-ДД>/` — **только вне папки скиллов**: копия внутри `~/.claude/skills/` загрузится как второй скилл с тем же описанием.

**3. Замер «до».** Сохрани скрипт из конца файла как `/tmp/skill_check.py` и запусти: `python3 /tmp/skill_check.py <папка-скиллов-или-скилла>`. Таблицу покажи человеку целиком.

**4. План.** По каждому скиллу — нарушения из замера и правила 1–7 ниже. Раздели на две колонки:

| Меняю сам (форма) | Только предлагаю (поведение) |
|---|---|
| переписать `description` по правилу 4, сохранив все слова-триггеры старого | удалить любой текст, даже «очевидный» (правило 5) |
| перенести справочный раздел из SKILL.md в отдельный файл **дословно** и дать на него ссылку | менять команды, флаги, версии API, числа, порядок шагов |
| поднять вложенную ссылку на уровень SKILL.md | менять `name` — сломается `/команда` |
| добавить оглавление файлу длиннее 100 строк | менять `disable-model-invocation`, `allowed-tools`, `model` |
| дать ссылку на файл скилла, на который никто не ссылается | исправить путь, если правильный неочевиден |
| исправить путь, если правильный файл существует и он один; файл из папки скилла — как `${CLAUDE_SKILL_DIR}/<файл>` | трогать скрипты, `.env`, ключи (ключи не открывать и не печатать) |

**5. Правки** — только после «да». Правила, которые человек вписал в скилл как свои («всегда…», «никогда…»), переносятся слово в слово.

**6. Проверка.** `python3 /tmp/skill_check.py <папка>` — снова; затем `python3 /tmp/skill_check.py --compare ~/skills-backup-<дата>/<скилл> <папка-скилла>`. Потерянной может быть только строка, переписанная по плану (путь, описание), — каждую назови в отчёте. Остальные верни и повтори проверку.

**6б. Прогон на задаче.** Если можешь запускать субагентов (в Claude Code — да), возьми настоящую задачу скилла и убери из неё всё необратимое: никаких запросов во внешние сервисы, записи и удаления, ключи не читать — только `test -f`. Дай её двум свежим субагентам, лучше на Haiku (правило 7): один работает по копии, другой — по новой версии. Каждый возвращает: какие файлы скилла открыл и сколько строк прочитал, какие пути проверил и нашлись ли они, итоговую команду или результат. Новая версия хуже хоть в одном пункте — откати эту правку и скажи человеку.

**7. Отчёт.** Таблица: скилл · строк SKILL.md до/после · символов в описании до/после · нарушений до/после · прогон задачи до/после. Ниже — «Предлагаю, не применял» и три запроса для проверки в новой сессии (правило 7).

## Семь правил

### 1. Файл длиннее 100 строк — оглавление в начале

Claude не обязан читать длинный файл скилла целиком: он может открыть только начало — в руководстве Anthropic прямо приведена команда `head -100` — и по нему решить, нужен ли файл дальше. Что ниже сотой строки, в этот момент для него не существует. Поэтому у каждого файла длиннее 100 строк в начале — оглавление: даже по первым строкам Claude видит, что в файле есть, и открывает нужный раздел.

### 2. Ссылки — на один уровень от SKILL.md, и каждый путь существует

Файл, до которого Claude доходит по ссылке из другого файла, он особенно склонен читать частично — тем же `head -100`. Все файлы — ссылкой прямо из SKILL.md. Файл, о котором SKILL.md молчит, для Claude не существует вовсе: по руководству, если Claude никогда не открывает файл скилла, он либо не нужен, либо на него плохо указано. Путь, которого нет на диске, Claude будет искать сам — и через раз найдёт. Файл из папки скилла в команде — через `${CLAUDE_SKILL_DIR}`: Claude Code подставит путь к папке скилла, а `cat .env` без пути ищет файл в папке проекта.

### 3. SKILL.md — до 500 строк, подробности — в отдельных файлах

При вызове SKILL.md целиком ложится в контекст. SKILL.md — оглавление; справочник, примеры, шаблоны — в файлы рядом, со ссылкой из SKILL.md: Claude прочитает их, только когда понадобятся. Скилл про несколько областей — по файлу на область: вопрос про продажи не грузит маркетинг.

### 4. Описание — что делает и когда применять

Claude видит заранее только `name` и `description` каждого скилла и по описанию выбирает нужный, по словам Anthropic — «из 100+». Описание без «когда» — причина, почему скилл то вызывается, то нет.

- Две части: что делает + когда применять (слова, которыми человек об этом попросит).
- От третьего лица: «Создаёт…», а не «Я помогу…» или «Ты можешь…» — описание встраивается в системный промпт.
- Ключевой сценарий — первым: в Claude Code `description` вместе с `when_to_use` обрезается на 1 536 символах, а когда скиллов много, описания редко вызываемых выпадают из списка целиком.
- Лимит поля — 1 024 символа.
- Скилл с `disable-model-invocation: true` вызывается только вручную, его описание в контекст не попадает — правило 4 к нему не применяется.

### 5. Только то, чего Claude не знает

Исходное допущение Anthropic: Claude уже очень умный. Каждый абзац — вопрос: нужно ли это объяснять, оправдывает ли он свои токены. Объяснения «что такое PDF», «что такое API» — кандидаты на вычерк. Проверка от противного — задача без скилла: что Claude делает верно и так, в скилле лишнее. **Вычерк только предлагать.**

### 6. Свобода — по хрупкости задачи, и петля проверки

- Много верных путей (ревью, пост, разбор звонка) — общие указания.
- Хрупкая операция (миграция, деплой, счёт, удаление) — точная команда или скрипт и «не меняй флаги». Скрипт выполняется, а не читается: в контекст идёт только вывод. Массовое и необратимое — план в файле → проверка плана → выполнение.
- Многошаговая работа — чек-лист, который Claude копирует и отмечает.
- Где важно качество — петля: проверил → исправил → проверил снова, дальше только когда проверка прошла.

### 7. Проверка на реальных задачах и всех своих моделях

Anthropic советует начинать с проверок, а не с текста: три реальных сценария до и после правки. Метод из руководства — Claude A пишет и правит скилл, свежий Claude B проверяет его на настоящей задаче; шаг 6б — ровно он. Что сработало на Opus, может требовать больше подробностей на Haiku — проверяй на тех моделях, которыми пользуешься. Три запроса для новой сессии: один должен вызвать скилл, второй — похожий, но не должен, третий — настоящая задача скилла от начала до конца.

### Ловушки Claude Code, которых в руководстве нет

- Копия скилла внутри `~/.claude/skills/` — для Claude ещё один скилл с тем же описанием. Копию — только вне папки скиллов.
- Команда выполняется из папки проекта, а не скилла: `cat .env` найдёт `.env` проекта или ничего. Файлы скилла в командах — через `${CLAUDE_SKILL_DIR}`.
- `description` вместе с `when_to_use` обрезается на 1 536 символах; когда скиллов много, описания редко вызываемых выпадают из списка целиком.
- У скилла с `disable-model-invocation: true` описание в контекст не попадает: он вызывается только `/командой`.

### Мелочи из того же руководства

- Не рассчитывай, что пакет уже стоит: рядом со скриптом — строка установки.
- `name`: строчные буквы, цифры, дефисы, до 64 символов, без слов `anthropic` и `claude`.
- Одно понятие — один термин на весь скилл.
- Никаких «до августа используй старый API»: устаревшее — в раздел «Старые способы».
- Пути — через `/`, не `\`.
- MCP-инструменты — полным именем `Сервер:инструмент`.
- Не предлагай пять вариантов — дай один по умолчанию и запасной.

## Скрипт замера

Сохрани как `/tmp/skill_check.py`. Только читает файлы, ничего не меняет.

```python
import os, re, sys
from pathlib import Path

def frontmatter(t):
    m = re.match(r'---\n(.*?)\n---\n?(.*)', t, re.S)
    if not m: return None, t
    fm = {}
    for k, v in re.findall(r'^([\w-]+):[ \t]*(.*(?:\n[ \t]+.*)*)', m.group(1), re.M):
        fm[k] = re.sub(r'\s+', ' ', v).strip().strip('"\'')
    return fm, m.group(2)

def md_links(text):
    return [l.split('#')[0] for l in re.findall(r'\]\(([^)\s]+)\)', text) if not re.match(r'(https?:|mailto:|#)', l)]

def check(skill):
    p = skill / 'SKILL.md'; t = p.read_text(encoding='utf-8'); fm, body = frontmatter(t); out = []
    if fm is None: return 0, 0, ['нет frontmatter']
    name, desc = fm.get('name', skill.name), fm.get('description', '')
    full = (desc + ' ' + fm.get('when_to_use', '')).strip()
    if not re.fullmatch(r'[a-z0-9-]{1,64}', name) or re.search(r'anthropic|claude', name): out.append(f'имя «{name}» вне правил')
    manual = fm.get('disable-model-invocation', '').lower() in ('true', 'yes', 'on', '1')
    if not desc: out.append('пустое описание')
    elif not manual and not re.search(r'when|trigger|\buse\b|когда|использ|применя|если|триггер|просьб|просит', full, re.I): out.append('в описании не видно, когда применять')
    elif len(desc) > 1024: out.append(f'описание {len(desc)} > 1024')
    if len(full) > 1536: out.append(f'описание + when_to_use {len(full)} > 1536')
    if re.search(r'\b(I can|I will|You can)\b|\b(я помогу|я могу|ты можешь|вы можете)\b', desc, re.I): out.append('описание не от третьего лица')
    lines = body.count('\n') + 1
    if lines > 500: out.append(f'SKILL.md {lines} строк > 500')
    files = [f for f in skill.rglob('*') if f.is_file() and f.suffix == '.md' and f.name != 'SKILL.md']
    named = lambda text, f: str(f.relative_to(skill)) in text or f.name in text
    linked = {f.resolve() for f in files if named(t, f)}
    for l in md_links(body):
        if not (skill / l).exists(): out.append(f'битая ссылка {l}')
    missing = [r for r in set(re.findall(r'(?<![\w./])(~/[\w./-]+|/(?:Users|home|opt|etc)/[\w./-]+)', t)) if not os.path.exists(os.path.expanduser(r.rstrip('.')))]
    out += [f'путь не существует {r}' for r in missing if '/skills/' in r]
    if any('/skills/' not in r for r in missing): out.append(f'(не найдено на этой машине, проверить вручную: {len([r for r in missing if "/skills/" not in r])} путей)')
    deep = {}
    for f in files:
        ft = f.read_text(encoding='utf-8', errors='ignore')
        for g in files:
            if g != f and g.resolve() not in linked and named(ft, g): deep.setdefault(g.resolve(), f.relative_to(skill))
    for f in files:
        ft = f.read_text(encoding='utf-8', errors='ignore'); rel = f.relative_to(skill)
        if f.resolve() in deep: out.append(f'{rel}: открывается только через {deep[f.resolve()]} (2-й уровень)')
        elif f.resolve() not in linked: out.append(f'{rel}: SKILL.md его не упоминает')
        if ft.count('\n') > 100 and not re.search(r'^#+\s*(Contents|Содержание|Оглавление)', '\n'.join(ft.splitlines()[:40]), re.M | re.I): out.append(f'{rel}: {ft.count(chr(10))} строк без оглавления')
    if '\\' in ''.join(md_links(body)): out.append('обратный слэш в путях')
    fence = '`' * 3
    code = '\n'.join(re.findall(fence + r'.*?\n(.*?)' + fence, t, re.S))
    for f in skill.rglob('*'):
        rel = str(f.relative_to(skill))
        if f.is_file() and f.suffix != '.md' and re.search(r'(?<![\w/}.~-])' + re.escape(rel) + r'(?![\w/-])', code):
            out.append(f'команда с {rel} без ${{CLAUDE_SKILL_DIR}}: сработает, только если Claude сам перейдёт в папку скилла')
    return lines, len(desc), out + (['(ручной вызов: описание не в контексте)'] if manual else [])

def compare(old, new):
    norm = lambda s: re.sub(r'\s+', ' ', s).strip()
    have = set()
    for f in Path(new).rglob('*.md'): have |= {norm(l) for l in f.read_text(encoding='utf-8').splitlines()}
    lost = [l for l in (Path(old) / 'SKILL.md').read_text(encoding='utf-8').splitlines() if norm(l) and norm(l) not in have and not norm(l).startswith('description:')]
    print(f'Потеряно строк: {len(lost)}'); [print('  -', l[:120]) for l in lost]

if __name__ == '__main__':
    if sys.argv[1] == '--compare': compare(sys.argv[2], sys.argv[3]); sys.exit()
    root = Path(sys.argv[1]).expanduser()
    skills = [root] if (root / 'SKILL.md').exists() else sorted(d for d in root.iterdir() if (d / 'SKILL.md').exists())
    total = 0
    for s in skills:
        lines, dlen, issues = check(s); n = sum(1 for i in issues if not i.startswith('('))
        total += n; print(f'{s.name:30} строк {lines:4}  описание {dlen:4}  нарушений {n}')
        for i in issues: print('   ·', i)
    print(f'\nСкиллов: {len(skills)}, нарушений: {total}')
```

Что скрипт не видит и проверяет агент глазами: насколько точно описание называет «когда» (правило 4; скрипт ищет только сами слова), лишние объяснения (правило 5), свобода и петли (правило 6), один термин на понятие.
