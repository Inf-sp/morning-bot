# Админ

Экран ошибок хранит записи за последние 24 часа. Одинаковые ошибки группируются с количеством повторов и последней датой; для сбоя AI показывается безопасная причина по провайдерам, а не сырой технический ответ. Слишком большой список компактно обрезается, чтобы экран всегда открывался. Фоновые probes не попадают в этот журнал: они обновляют строку состояния сервиса, а ошибки показываются здесь только после реального действия бота.

Роль: администратор бота, владелец `config.CHAT_ID`.

Панель отвечает на три вопроса: всё ли работает, есть ли проблемы и кто
пользуется ботом.

После запуска новой версии администратор получает одно уведомление с номером
версии и списком изменений. Строки состояния из `RELEASE_NOTES.md` (`Готово к
развёртыванию` и `Бот развёрнут и работает`) в список изменений не включаются:
итоговый статус `Бот развёрнут и работает ✅` показывается один раз внизу карточки.
В заголовке жирным выделяется только номер версии. После заголовка всегда идёт
одна пустая строка, затем подпись `Что изменено:` и 1–4 отдельных коротких
пункта: один пункт описывает одно изменение, без точки в конце. Итоговый статус
показывается обычным текстом.

## Навигация

```text
🛠 Админ
├── 🛠 Система
└── 👥 Пользователи
    ├── ➕ Инвайт
    └── ✉️ Приветствие
```

Админка состоит из двух основных экранов: `🛠 Система` и `👥 Пользователи`.
Все кнопки главного экрана стоят по одной в строке.

Актуальные ошибки показываются сразу под общим статусом и отдельным жирным заголовком `Ошибки:` без эмодзи. Отдельной кнопки ошибок нет; скрытая команда
`/admin_logs` сохранена для полного журнала.

## 🛠 Админ

Главный экран показывает только один общий статус API и время локального снимка:
`🟢 API работают · обновлено в 12:32`. При ограничениях строка становится жёлтой,
при пользовательской недоступности — красной. Если снимок старше 15 минут,
показывается `⚪ Состояние API неизвестно · данные от 12:32`.

Состояния внешних сервисов читаются из сохранённого снимка фонового мониторинга.
При открытии выполняется только быстрый прямой запрос к PostgreSQL; провайдеры
последовательно не опрашиваются. Если последний снимок старше 15 минут, время
обновления получает пометку `данные устарели`.

Если `DATABASE_URL` настроен, сбой PostgreSQL никогда не маскируется временным
in-memory-хранилищем: запись завершается ошибкой и не выдаётся пользователю за
сохранённую. In-memory backend используется только локально без `DATABASE_URL`.

На главном экране нет отдельных строк PostgreSQL, уведомлений, пользователей,
квот и провайдеров; ниже статуса видны до пяти актуальных ошибок. Кнопки `🛠 Система`, `👥 Пользователи` и
`#️⃣ Главная` стоят в отдельных строках; подробности открываются только по нажатию.

Внизу — `⬅️ Назад` (в личные настройки) и `#️⃣ Главная` (в главное меню бота), как
на всех экранах бота.

## 🛠 Система

Экран использует обычный текст Telegram, поэтому размер шрифта одинаков на всех
устройствах. `AI` и `Данные` показаны компактными блоками `Сервис · Состояние`. Полный журнал ошибок остаётся доступен через `/admin_logs`.

Отдельный монитор проверяет AI-провайдеры, внешние API, Telegram и хранилище,
а экран только читает сохранённые состояния. Фоновый цикл просыпается каждые
5 минут, но каждый провайдер проверяется не чаще своего интервала — обычно раз
в час; результат любого обычного API-запроса обновляет то же состояние сразу.
Реальный запрос и фоновая проверка используют один переход состояния: квота,
ошибка, восстановление и выбранный резерв не могут расходиться между двумя
журналами.
Проверка доступности Gemini (`models.list`) служит только диагностике на этом
экране: она не меняет порядок AI-цепочки. Переключение на резерв для реального
ответа происходит только после успешного резервного ответа на пользовательский
запрос.
Проверки, которые сами расходуют платную квоту или лимит запросов (AI-провайдеры,
Spoonacular и ZeroEntropy), выполняются не чаще раза в час; между ними монитор
использует результаты реальных обращений, чтобы диагностика не исчерпывала лимит сервиса.
Доступ к Google Books проверяется не чаще раза в сутки официальным поисковым
запросом одной книги; реальные обращения раздела обновляют тот же статус сразу.
При временной ошибке Google Books повторяет запрос до двух раз с короткой паузой,
после чего карточка книги продолжает работать через Open Library.
Если эта проверка завершилась временной сетевой или серверной ошибкой,
существующий монитор повторяет её не чаще чем через 30 минут. Ошибки ключа и доступа так не
повторяются.
Для Google Books дополнительно хранятся только текущая дата и число фактических
запросов за день; ответы из суточного кэша счётчик не увеличивают.
AI-провайдеры отображаются по роли и состоянию следующего запроса. Вся
маршрутизация и резервирование определяются единым AI-слоем.
Gemini не является обязательным условием запуска: если его ключ не настроен,
бот стартует с другими доступными AI-провайдерами, а строка Gemini показывает
отсутствующую конфигурацию.
Невалидный structured-ответ (например, сломанный JSON) считается неуспешной
попыткой: он не передаётся в раздел и не перезапрашивается у той же модели, а
сразу запускает следующий резерв маршрута.
Каждый сервис хранит одинаковые поля: статус, подтверждённую квоту, выбранный
резерв, последнюю проверку, последний успех и последнюю ошибку.

Экран группирует сервисы по назначению:

```text
AI
🟢 Groq · Основной · 12 сегодня
🟢 Gemini · Сложные задачи · 7 сегодня
🟢 Cloudflare AI · Резерв · 318 нейронов сегодня
🟢 OpenRouter · Последний резерв · 3 сегодня

Данные
🟢 OpenWeather · Погода · 24 сегодня
```

Для Groq показывается одна общая строка провайдера. Внутренние модели и их
названия на пользовательском экране не отображаются; расход их запросов суммируется.
Для Cloudflare экран показывает фактический расход нейронов за сегодня.

Каждая строка имеет формат:

```text
эмодзи Сервис · роль или область · статус или статистика
```

Зелёная строка не повторяет слова «работает», «доступен» или «в норме».
Подтверждённая самим API квота выводится как `N/M осталось`, исчерпанная — как
`лимит исчерпан`. При значении не более 20% строка становится жёлтой. Если API
не сообщает квоту или rate-limit-заголовки, экран показывает только фактический
расход за текущий период. Локальные ориентиры и дневные бюджеты не выдают себя
за лимит провайдера и не делают строку жёлтой. Ответ `429` показывается как
`слишком много запросов`, а не как исчерпанная квота. AI использует роли `Основной`,
`Сложные задачи`, `Резерв` и `Последний резерв`; внешние данные — конкретную
область вроде `Погода`, `Поиск` или `Фото`.

Примеры полезных строк: Gemini и Groq показывают число запросов сегодня,
Cloudflare AI — число нейронов, LanguageTool — число проверок, gTTS —
число символов. Groq, OpenRouter, Spoonacular и другие API показывают остаток
только из ответа или rate-limit-заголовков, когда сервис его сообщает.
У Groq жёлтый статус появляется только когда подтверждённый остаток опускается
ниже половины дневного лимита: при лимите 1 000 — с 499 запросов.
Ответ Spoonacular `402` показывается как исчерпанный дневной лимит, а не как
неопределённый статус.

Резерв проверяется до переключения и появляется в конце строки только после
реального выбора, без слов «используется резерв». Направленный граф резервов
проверяется на циклы; у поиска разрешено только направление Firecrawl → Tavily,
а у туристических фотографий — Pexels → Unsplash.

Если Tavily подтвердил исчерпание месячных credits, он получает отдельную общую
блокировку до первого дня следующего календарного месяца. До этой даты ни поиск,
ни фоновый монитор не делают к Tavily HTTP-запросов; Firecrawl продолжает работать.
Строка показывает только «лимит исчерпан» и не сообщает о восстановлении, пока
первый реальный запрос нового месяца не завершится успешно.
Tavily имеет ориентир 1 000 credits в месяц: после 900 включается экономный режим,
в котором остаются только официальная медицина и явный пользовательский research.
В технической статистике сохраняются сценарий, basic/advanced-вызовы, расход,
cache hits и пропуски по policy или квоте.

`⚪` означает, что сервис ещё не проверялся. `🟡` означает ограничение,
временную ошибку или работу через резерв.
`🔴` допустим только когда функция действительно не работает и рабочего
резерва нет. HTTP-коды, traceback, `NameError`, timeout и ошибки разбора JSON
на этом экране не показываются: они переводятся в понятные формулировки.
Нераспознанный результат фоновой проверки не считается поломкой: он остаётся
нейтральным до первого подтверждённого результата, без строки «не удалось
определить статус».
Для Google Books отдельно различаются неверный ключ, отключённый API, запрет
доступа, дневной лимит, слишком частые запросы, недоступность Google и отсутствие
соединения. При успешной проверке строка показывает локальный остаток:
`🟢 Google Books · Книги · 963/1 000 осталось`. Положительный остаток остаётся
зелёным: статус меняется только после реального лимита или сбоя.
После 1 000 запросов Google больше не вызывается,
а строка сообщает, что используется Open Library.

Здоровые Telegram и PostgreSQL не выводятся: это инфраструктура, а не квоты.
При проблеме они появляются как `🔴 Telegram · ошибка отправки` или
`🔴 PostgreSQL · нет подключения`. TheMealDB скрыт, пока не используется как
реальный резерв Spoonacular; тогда строка Spoonacular заканчивается на
`→ TheMealDB`.
Успешная проверка Spoonacular с положительным остатком сразу возвращает готовку
к первичному источнику и убирает старую стрелку резерва.

Экран не показывает служебные строки про автоматический резерв, модель AI,
процентиль времени ответа и число медленных действий. Для каждого подключения
остаётся только актуальный статус, область использования и понятный остаток
лимита либо причина ограничения. Сырая последняя ошибка на экран не выводится.
Ниже остаётся стандартная строка `⬅️ Назад | #️⃣ Главная`.

## 👥 Пользователи

Экран показывает сводку (без `user_id`, `chat_id`, последних сообщений), а ниже -
список пользователей: индикатор свежести (🟢/🟡/🔴), имя и когда последний раз
заходил. Список отсортирован по свежести активности, показывает до 15 записей;
если пользователей больше, внизу видно, сколько ещё не показано. Первая кнопка -
`➕ Инвайт`. Отдельной кнопки "Обновить" нет - открытие экрана уже показывает
свежие данные.

`➕ Инвайт` сначала открывает экран описания, затем кнопка `✅ Создать` генерирует
одноразовую ссылку. `✉️ Приветствие` показывает текст, который увидит новый
пользователь после входа.

## ⚠️ Ошибки

Экран показывает все реальные ошибки за 24 часа. Обычные успешные проверки,
переключение на резерв и восстановление не входят в счётчик ошибок и не создают
отдельные строки. События мониторинга имеют тип `error`, `fallback`, `recovery`,
`status` или `system` и связываются одним `incident_id`.

Цепочка «ошибка → резерв → восстановление» не попадает в список ошибок, если
резерв ответил или основной сервис восстановился: пользователь не потерял
функцию. Она сохраняется во внутренней истории для диагностики. HTTP-коды,
длительность, имена внутренних цепочек и пути к файлам на экран не выводятся.
Лимит основного AI-провайдера не помечается как потерянный ответ, если запрос
успешно завершил резерв.
В начале экрана «Система» показывается строка `Ответы`: время, в которое
укладываются 95% действий за последние сутки, и число действий дольше своего
лимита. Содержание сообщений и ответов в этой статистике не хранится.
Для AI-действий технический след сохраняет только маршрут: запрошенный tier,
основной провайдер и его статус, финальный провайдер и число вызовов Gemini.
Это позволяет отличить cache-hit от fallback без сохранения prompt или ответа.
Лимит сервиса считается восстановленным только после реального успешного запроса:
служебная проверка доступности не закрывает квотный инцидент. Для Tavily ответ
`HTTP 432` показывается как исчерпанный лимит тарифа.
Повторная успешная проверка при неизменном состоянии в историю не записывается.
Ошибка приложения занимает одну строку: дату, время, конкретный раздел и действие пользователя. Ошибки AI из разных разделов не объединяются; вместо общей подписи «Разные категории» используется раздел текущего действия, например `Словарь`, `Питание` или `Кино`. Ошибки сохранения JSON остаются ошибками раздела, а не выдаются за сбой AI-резервов.
Для AI-сбоев не выводятся текст ответа провайдера, имя модели или место в коде; вместо этого
видна понятная причина, например `Groq — лимит; OpenRouter — сервис не ответил`.
Если все резервы временно недоступны, пользователь получает короткий безопасный ответ,
а журнал не дублирует один и тот же инцидент строкой «Ассистент · не удалось подготовить ответ»:
остаются только системные причины по затронутым провайдерам.
Отдельных кнопок копирования нет.
Дата и время каждой записи показываются в часовом поясе бота `Europe/Amsterdam`, а не
в системном UTC-времени сервера Railway.
Одинаковые ошибки фоновой проверки одного сервиса, возникшие в пределах десяти
минут, показываются одной строкой со счётчиком повторов. Ticketmaster проверяется
в фоне не чаще одного раза в час, поэтому открывать раздел «Концерты» для такой
проверки не требуется.

Секреты перед сохранением и повторно перед показом заменяются на `[REDACTED]`.
Открытие экрана сохраняет для каждого администратора позицию просмотра; главный
экран после этого показывает только появившиеся позже ошибки. Кнопка `❌ Очистить ошибки`
очищает ошибки приложений и инциденты сервисов. Навигация остаётся
стандартной: `⬅️ Назад | #️⃣ Главная`.
В список попадает только активная проблема без рабочего резерва; одинаковые
активные записи сворачиваются в одну строку с количеством повторов.

Например: `🟡 Gemini · Сложные задачи · лимит исчерпан · Groq`. Raw-ответы API,
stack trace и тело ошибки на главном экране не показываются.
