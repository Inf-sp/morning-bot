# morning-bot — AGENTS.md

## Приоритет правил

1. Текущее задание владельца
2. Этот файл
3. Актуальный `docs/<feature>.md`
4. Реальный код и стиль соседних модулей

`morning-bot` — персональный Telegram-бот на Python. Он должен ощущаться как
короткий и надёжный личный помощник, а не как набор функций.

## Рабочий подход

- Сначала проверь пользовательский сценарий и найди реальный модуль, связанный
  `ui/*.py`, feature-doc и соседний код.
- Меняй минимально нужный участок; не добавляй архитектуру «на будущее».
- Сохраняй данные, callback-и и соседние сценарии.
- Не раскрывай пользователю внутренние модели, провайдеры, id, traceback и raw errors.
- При изменении поведения обновляй соответствующий `docs/*.md`.
- `RELEASE_NOTES.md` в проекте не используется и не создаётся.
- Владелец самостоятельно отправляет изменения в Git и Railway.

## Команды

```bash
python -m pip install -r requirements.txt
python bot.py
python -m py_compile path/to/changed_file.py
python routing.py                 # после изменения callback-ов
python verify.py                  # когда нужна общая проверка контрактов
python -m pytest -q path::test    # только целевые тесты
```

Railway запускает `python bot.py`. Не деплой и не меняй Railway без прямой просьбы.
Не запускай полный `pytest` после небольших правок. Не хардкодь секреты, токены,
лимиты и настройки из env, `config.py`, `settings.py` или runtime-слоя.

## Архитектурные границы

- `bot.py`, `bot_callbacks.py` — вход и маршрутизация.
- Feature-модули (`myday.py`, `wardrobe.py`, `cooking.py`, `learning*.py`,
  `leisure_*.py`, `travel.py`) — сценарии и бизнес-логика.
- `ui/*.py` — только текст, форматирование и кнопки; без store, AI, сети и решений.
- `store.py`, `storage_driver.py`, `repositories.py` — хранение.
- `provider_runtime.py`, `ai.py` — централизованный выбор AI, fallback, cooldown,
  лимиты, кэш и нормализация ошибок.
- Провайдеры и внешние API не выбираются внутри feature-модулей, если есть общий слой.
- `MessageBuilder` используется для Telegram-разметки; UTF-16 offsets нельзя
  пересчитывать вручную байтовыми индексами.
- Для списков и удаления сначала проверь возможность использовать `cleanup.py`.
- Большие значения не храни в `callback_data`; используй короткий стабильный id.

## AI, сеть и данные

До LLM проверь: правила/шаблон → store → свежий кэш → внешний источник → AI.
LLM нужен для персонализации, свободного текста, объяснений и суммаризации, но не
для меню, кнопок, пагинации, сортировки, статусов и простого форматирования.

- По возможности LLM возвращает structured data, Telegram-текст собирает код.
- Любой AI-сценарий использует общую цепочку резервов; feature не повторяет её сам.
- У пользовательского сценария должен быть безопасный fallback без AI, где это возможно.
- Кэш учитывает только влияющие параметры: user, feature, язык/уровень, город,
  input hash, profile version и date bucket.
- Изменение входных данных меняет hash/version или явно очищает нужный кэш.
- Рекомендации используют `recommendation_rotation.py`: свежие варианты раньше
  повторов, текущая карточка не возвращается первой после полного круга.
- Не перезаписывай весь профиль ради одного поля; новые поля имеют fallback, старые
  профили продолжают работать.
- PostgreSQL — основной backend при `DATABASE_URL`; memory fallback допустим только
  локально без этой переменной.

Автоматический внешний поиск формируется на английском. Источники читаются на
английском или языке оригинала; пользователь получает русский текст. Имена людей,
произведений, заведений, площадок и брендов сохраняются оригинальными. Непроверяемые
актуальные факты, даты, безопасность и релизы не выдумывать.

## Общий UI-контракт

- Пользовательский UI — на русском; изучаемый язык и оригинальные названия сохраняются.
- После главного заголовка одна пустая строка; один экран — одна главная задача.
- Используй `·` для компактных метаданных; обычно достаточно 3–5 пунктов.
- Полезные результаты сохраняются в истории; временные меню можно заменять.
- Не создавай несколько конкурирующих меню.
- Основной раздел сразу показывает полезный персональный результат, кроме агрегатора
  `☀️ Мой день` и `🎚️ Настройки`.

Единые кнопки:

```text
⬅️ Назад
#️⃣ Главная
✅ Добавить ...
❌ Удалить / очистить ...
📝 Предпочтения
🎚️ Настройки / Мой ...
✨ Подобрать ...   # результата ещё нет
✨ Другой ...      # результат уже показан
```

Не использовать `#️⃣ Меню`, `🗑`, универсальное `*️⃣ Выбрать ...` и длинные
варианты `⬅️ Назад в ...`. Опасные действия требуют подтверждения.

Главное меню:

```text
☀️ Мой день
🧵 Гардероб
🥣 Готовка
🧠 Обучение
✈️ Поездки
🎬 Кино
🎧 Музыка
📚 Книги
👾 Игры
🎚️ Настройки
```

Детальные тексты, кнопки и продуктовые правила разделов определены только в
соответствующих feature-doc, а не дублируются здесь.

## Проверка и завершение

После правки:

1. Запусти `py_compile` изменённых Python-файлов.
2. Выполни только релевантные тесты чистых функций и изменённого сценария.
3. После callback-изменений проверь `routing.py`.
4. Обнови feature-doc при изменении поведения.
5. Не утверждай, что проверка прошла, если она не запускалась; отделяй новые ошибки
   от уже существующих.

Задача готова, когда UX не усложнился, навигация едина, callback-и не конфликтуют,
UI не обращается к store/AI, AI идёт через общий слой, кэш не обходит свежие данные,
пользовательские данные сохранены и выполнена соразмерная техническая проверка.

Финальный ответ владельцу — короткий:

```text
Готово.

Изменено:
- ...

Обновлено:
- docs/...

Проверено:
- ...
```
